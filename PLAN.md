Термины: **ES-модуль** — JS-файл, подключающий другие через `import`, без сборщика. **Веб-приложение Apps Script** — скрипт с адресом в интернете; на запрос Google запускает нашу функцию. **Service worker** — фоновый скрипт, который сохраняет сайт и данные в телефоне для работы без сети. **Идемпотентность** — повторная отправка того же изменения не создаёт дубль.

## Данные (листы Google Таблицы)
| Лист | Что хранит | Поля |
|---|---|---|
| **Шаблон** | пары семестра (≈30 строк) | `id` (напр. `ВТ-1500-ниж`), `неделя` (верх/низ/обе), `день` (1–6), `слотов` (1/2), `начало`, `конец`, `предмет` (ГПП), `полное`, `тип` (лекция/семинар), `аудитория`, `преподаватель`, `пометка` (постоянная: «Сменка», «отмечает сама») |
| **Правила** | изменения «с этой даты и дальше» | `id_пары`, `с_даты`, `по_дату` (пусто = до конца семестра), `поле` (аудитория/начало/конец/преподаватель), `значение`, `кто`, `обновлено` |
| **Записи** | ДЗ и разовые изменения пары шаблона в конкретную дату | `дата`, `id_пары`, `дз`, `нет_дз` (отметка «ДЗ нет»), `ссылки` (по одной на строку), `аудитория`, `начало`, `конец`, `преподаватель` (пусто = без замены), `отменена`, `причина`, `версия`, `кто`, `обновлено` |
| **Доп_пары** | переносы и дополнительные пары | `id` (`X-20261105-1`), `дата`, `начало`, `конец`, `предмет`, `полное`, `тип`, `аудитория`, `преподаватель`, `источник_дата`, `источник_id` (пусто = доп. пара), `дз`, `ссылки`, `отменена`, `версия`, `кто`, `обновлено` |
| **Дни** | пометки дня | `дата`, `пометка`, `кто`, `обновлено` |
| **Журнал** | каждое изменение | `когда`, `кто`, `действие`, `лист`, `ключ`, `было` (JSON), `стало` (JSON), `op_id` |
| **Настройки** | параметры | `опорная_неделя` = 2026-09-14, `опорная_половина` = верх, подписи недель, `завтра_после` = 18:30, `начало_семестра` = 2026-09-14, `конец_семестра` = 2026-12-31, `сетка_звонков`, `эмодзи_дней`, `фразы_по_умолчанию` |

**Коды активистов** — в Script Properties как SHA-256-хеш кода → имя (даже владелец, открыв настройки, не видит сами коды). Не в таблице, не в коде сайта.

**Как собирается день (одна функция, покрыта тестами):**
1. половина недели = (дни от опорной недели ÷ 7) чётное → опорная, иначе другая;
2. пары шаблона «эта половина» + «обе»;
3. применяем **Правила**, действующие на эту дату;
4. применяем **Записи** этой даты (разовые замены, ДЗ, отмена);
5. пары, у которых есть строка «Доп_пары» с `источник_дата/источник_id` = эта пара → помечаем «перенесена на …» (зачёркнутые);
6. добавляем «Доп_пары» на эту дату (с пометкой «перенос с …» или «доп. пара»);
7. сортируем по времени, **нумеруем по порядку в дне** (сдвоенная = два номера), зачёркнутые не нумеруем;
8. пометки шаблона + пометка дня.

«Сегодня» — по московскому времени через `Intl` независимо от часового пояса телефона.

**Персональные данные:** имена преподавателей (из официального расписания), имена активистов в журнале, возможные имена одногруппников в ДЗ (по правилам — без фамилий). Учётных записей, адресов, данных устройств не собираем.

## Шаги сборки
1. **Скелет + вся логика сборки дня.** Папки, `git init`, `seed.json`, `schedule.js` (пункты 1–8 выше).
   Готово, когда: `node --test` проходит: верх/низ (14.09, 28.09, 26.10 → верх; 21.09, 19.10 → низ), правило «с даты» не задевает прошлые недели, перенос (в т. ч. повторный и отменённый), доп. пара, нумерация как у активистов (включая «3⃣4⃣»); простая `index.html` показывает вторник 27.10 как в сообщении 44.
2. **Просмотр для группы на эталонных данных.** Вкладки Сегодня / Завтра / Неделя / ДЗ, «Идёт сейчас» с прогрессом пары, лента дня, плитки предметов, штампы, шрифты из `site/fonts/`, листание недель, «завтра» после 18:30 и с субботы на понедельник, карточки, зачёркнутые перенесённые/отменённые, метка «изменено» (48 ч); вёрстка под телефон.
   Готово, когда: все недели 14.09–31.10 совпадают с перепиской; Playwright: 360 px без горизонтальной прокрутки; при подмене времени 10:00 — текущий день, 19:00 — следующий.
3. **Google Таблица: чтение.** `Code.gs`: `setup()` создаёт листы и заполняет шаблон; `doGet()` отдаёт данные с кэшем; `api.js` — «сначала сохранённое, потом свежее». Таблицу и публикацию делаете вы по пошаговой инструкции. Первым делом проверяем CORS (правило браузера о запросах к чужим адресам) [не проверено на нашем проекте].
   Готово, когда: сайт показывает данные из таблицы; правка ячейки видна на сайте ≤ 5 мин.
4. **Редактор: ДЗ и пометки + надёжное сохранение.** `admin.html`: вход по личному коду, авто-выбор недели, полоса дней, плашка и **мастер «Заполнить»** с «ДЗ нет», список дней и пар с плитками и штампами, карточка пары снизу, автосохранение, «Отменить» 10 с, индикатор сохранения, очередь без сети, конфликт двух правок, журнал. `doPost`: проверка кода и данных, `LockService`, версии, `op_id`, защита от перебора.
   Готово, когда: верный код сохраняет, неверный — отказ без изменений, 10 ошибок → пауза; правка в офлайне доходит после появления сети без дублей (Playwright); одновременная правка показывает выбор; журнал пишет каждое изменение. **После этого шага — показ активистам.**
5. **Помощники ДЗ.** «Вставить ссылку» (буфер, разделение текста и ссылок), проверка темы (соответствие выучивается из прошлых записей), «Как в прошлый раз», частые фразы для предмета.
   Готово, когда: тесты `helpers.js` на ссылках из переписки (включая «чужие» чаты и YouTube); ДЗ «подпись + ссылка» ≤ 4 нажатий, «как в прошлый раз» — 2 (Playwright считает нажатия).
6. **Изменения расписания.** Замена аудитории/времени/преподавателя «только в этот день / с этого дня и дальше», отмена с причиной и возврат, перенос с предпросмотром и предупреждениями, доп. пара, пометка дня с вариантами.
   Готово, когда: разовая замена ≤ 15 с, перенос ≤ 1 мин; правило «с даты» меняет только будущие недели; перенос и его отмена отображаются в обоих днях как в брифе.
7. **Тексты для Telegram.** Неделя, по дням (последовательное копирование), текст об изменении; эмодзи дней из настроек.
   Готово, когда: тест сравнивает текст недели 26.10–31.10 с сообщениями 43–48; копирование дня — 1 нажатие; для переноса формируется строка «❗ …».
8. **Офлайн, PWA, закрытие от поиска, подсказки первого запуска.** `manifest`, значки, `sw.js`, `noindex` + `robots.txt`, 3 подсказки для активиста, раздел README «Для активистов».
   Готово, когда: офлайн открывается последняя неделя; браузер предлагает установить; noindex на всех страницах; заполнение недели 26.10 с телефона ≤ 5 мин (замер вместе с вами).

Публикация на GitHub Pages — этап 6 конвейера (выпуск), каждое действие с вашего разрешения.

## Зависимости
Устанавливаемых пакетов нет. Файлы шрифтов (3 семейства, OFL-1.1) копируются в `site/fonts/` один раз вместе с текстом лицензии. Браузерные API, Node v22 (уже на Mac), Playwright 1.63.0 (уже в облачной среде Claude). Новые зависимости — только с отдельного согласия.

## Безопасность
- Секретов в репозитории нет: хеши кодов — только в Script Properties; адрес веб-приложения не секрет. `.gitignore`: `.env`, `.DS_Store`, `node_modules/`, `materials/`.
- Проверка кода только в Apps Script: хеш SHA-256 (через `Utilities.computeDigest`, своей криптографии не пишем) сравнивается со списком; неверные попытки считаются в `CacheService`, 10 подряд → пауза 10 минут.
- Проверка входных данных в `doPost`: даты ГГГГ-ММ-ДД в пределах семестра; `id_пары` существует; время ЧЧ:ММ, конец позже начала; текст ≤ 5000 знаков, предмет ≤ 100; ссылки только `http(s)://`, не больше 10 на пару; не больше 8 доп. пар в день; неизвестные поля отбрасываются.
- Вывод только через `textContent` и безопасно созданные ссылки (`rel="noopener noreferrer"`), без `innerHTML` с пользовательским текстом — защита от XSS (внедрения чужого скрипта в страницу).
- `@OnlyCurrentDoc` — скрипт видит только эту таблицу, а не весь Диск.
- Веб-приложение: «Выполнять от моего имени, доступ — все» (иначе группа без Google-аккаунтов ничего не увидит); саму таблицу по ссылке видите только вы.
- Одновременная запись — `LockService` + `версия` строки; повторная отправка — по `op_id`, без дублей.
- Код «запомнить на этом телефоне» лежит в браузере активиста; кнопка «Выйти»; при утечке меняется один код.
- noindex + ссылка только внутри группы (152-ФЗ, см. бриф).

## Тестирование
- `node --test`: всё из «Как собирается день», «сегодня/завтра» (вечер, суббота, воскресенье, московское время), тексты Telegram (эталон 43–48), помощники (разбор вставок, темы ссылок, фразы, «как в прошлый раз»), проверка данных.
- Playwright (облачная среда): 360 px; подмена времени; офлайн-просмотр; офлайн-очередь редактора; конфликт двух вкладок; счёт нажатий для целевых сценариев; тестовая копия скрипта.
- Вручную вместе с вами: реальная таблица и публикация; заполнение недели с телефона на секундомер; неверный код; показ активистам после шага 4.

## Риски
- **CORS при запросах к скрипту** — чтение проверено 31.10.2026: запрос с чужого сайта (example.com) получил данные, статус 200. Для записи (шаг 4) — отправка как `text/plain`, без предварительного запроса.
- **Медленный первый ответ Apps Script (замерено: 4,6 с при холодном старте)** — сначала показываем сохранённое, потом обновляем; правки активиста видны у него сразу, отправка идёт в фоне.
- **Лимиты Apps Script** — для группы с запасом [точные цифры не проверены; сверим со страницей квот Google на шаге 3].
- **Буфер обмена на iPhone** требует разрешения при каждой вставке или не работает вне жеста пользователя — запасной путь: обычное поле, куда ссылку вставляют долгим нажатием.
- **Выученное соответствие «тема → предмет» может ошибиться** — поэтому только предупреждение, без запрета.
- **Объём выше исходного** — шаги упорядочены так, что после шага 4 уже есть рабочий редактор для показа активистам.
- **Git в подключённой папке** удаляет служебные файлы — на сборке попрошу один раз разрешение на удаление в папке «Расписание».
- **Сервисы Google в РФ** — данные всегда выгружаются из таблицы.
- **Смена семестра** — новый шаблон в лист «Шаблон», опорная неделя и даты — в «Настройки».

## Ключевые решения простыми словами
1. **Без сборщиков и фреймворков** — обычные HTML, CSS, JavaScript; лучший вариант для обучения и бесплатного хостинга.
2. **Вся логика — в двух модулях с тестами на реальных неделях** из переписки: мы доказуемо знаем, что расписание собирается правильно.
3. **Google Таблица = база данных, Apps Script = сервер** — бесплатно, данные видны человеку.
4. **Чётность от опорной недели** 14.09.2026 = верхняя — ошибиться нельзя.
5. **Номера пар и «перенесена» не хранятся, а вычисляются** — после любой правки всё сходится само.
6. **Редактор под реальные привычки активистов**: «как в прошлый раз», вставка ссылки одной кнопкой, частые фразы, замены «с этого дня» — потому что в переписке ссылки и пометки повторяются из недели в неделю.
7. **Ничего не теряется**: автосохранение, работа без сети, журнал, «Отменить», личные коды.

## Данные 0.2
**Новый лист «Версии»:** `id` (V1, V2…), `с_даты`, `опорная_неделя` (понедельник), `опорная_половина`, `начало_семестра`, `конец_семестра`, `версия` (счётчик правок — для конфликтов), `кто`, `обновлено`.
**Лист «Шаблон»:** новый столбец `версия_шаблона` — строка = пара конкретной версии. `id` пары **сохраняется при копировании** версии (ДЗ и замены привязаны к `id_пары` + дата, поэтому продолжают работать); новая пара получает новый `id`, которого нет ни в одной версии.
**Лист «Настройки»:** остаётся `завтра_после`; опорная неделя и даты семестра переезжают в «Версии».
**Переход (функция `migrateV2`, запускается один раз):** создаёт «Версии» с V1 «с 14.09.2026» из нынешних «Настроек», проставляет V1 всем строкам «Шаблона», ничего не удаляет из «Записей», «Правил», «Доп_пар». Сервер новой версии работает и до, и после перехода (если листа «Версии» нет — собирает V1 из «Настроек»), поэтому порядок «сервер → переход → сайт» без простоя.

**Как собирается день (меняются шаги 1–3):**
1. версия = последняя, у которой `с_даты` ≤ дата (до первой версии — первая);
2. верх/низ — от опорной недели **этой версии**;
3. постоянная замена действует, только если началась не раньше версии (`с_даты` правила ≥ `с_даты` версии); замены прошлого семестра в новый не переходят;
4–8 — как в 0.1.
Пара по `id` для переноса, текстов Telegram и помощников ищется в версии на нужную дату (если её там нет — в ближайшей версии, где она есть), а не в общем «шаблоне».

**Что отдаёт сервер:** `versions` (с парами), `subjects`, правила, записи, доп. пары, пометки, `tomorrowAfter`. Для открытых у кого-то старых версий сайта остаются прежние поля `template` и `settings` (версия, действующая сегодня).
**Имена:** поле `кто` не попадает ни в ответ чтения, ни в ответы на правки (в том числе `current` в конфликте), ни в память ответов в кэше. Остаётся `обновлено` — для метки «изменено недавно».

**Новые операции (только с сетью):**
- `version.save` — версия целиком: даты, опорная неделя, пары; с номером версии (две одновременные правки → конфликт, а не затирание). Создать можно с даты не раньше завтрашней (по Москве); менять и удалять (`version.remove`) — только ещё не наступившую.
- `subject.set` — предмет: сокращение, полное название, цвет из палитры. Ключ предмета не переименовывается (на него ссылаются пары), полное название — можно.
- Импорт — обычные операции `entry` и `note.add`, отправленные одной пачкой.

**Персональные данные:** без изменений по составу; имена активистов теперь только в таблице.

## Решения, которые уточняют бриф
1. **Действующую версию не правим — создаём новую «с завтра».** Так «прошлое не меняется» выполняется всегда, даже для исправления опечатки. При создании копии значения действующих **бессрочных** постоянных замен подставляются в пары новой версии (видно в предпросмотре); замены с датой «по» перечисляются в предупреждении. Иначе новая версия посреди семестра тихо откатила бы, например, новую аудиторию.
2. **Последствия правки** (функция `templateImpact`, с тестами): для ДЗ, разовых замен и переносов на датах версии у пар, которые сменили день/половину или исчезли, — «Перенести на эту же пару в новый день той же недели» (если такая дата есть) / «Оставить в таблице (на сайте не видно)» / общая «Отменить правку». Правило «с этого дня» на изменённой паре — предупреждение «замена останется сильнее шаблона». Ничего не удаляется: строки остаются в таблице и вернутся, если правку отменить.
3. **«С этого дня и дальше» при наличии будущей версии** показывает «до 08.02.2027 (дальше — новый шаблон)», чтобы активист не думал, что замена перейдёт в новый семестр.
4. **Импорт:** пара находится по дате и времени начала (запасной путь — по предмету и порядку); строки «❗/❌/➡️», отмены и переносы — в «не удалось отнести»; строки, совпадающие с постоянной пометкой пары («Сменка»), пропускаются; текст под парой без ДЗ («занятие», напр. физкультура) — пометка дня. Текст сохраняется как написан, вместе с эмодзи («Сдаём КСУ🤩»); тест сверки с историей сравнивает без эмодзи (в истории проекта эмодзи было убрано вручную). Если в сообщении нет даты — день берётся из открытой недели по названию дня.
5. **Проверка «сломанный сценарий не выкладывается»** — на отдельной ветке (`ci-check`), где проверки идут, а выкладка разрешена только из `main`. Так не рискуем рабочим сайтом. Нужна ваша команда на отправку ветки.

## Найдено при проверке текущего кода (войдёт в шаги)
- **Кэш сервера может сломать сайт целиком (ошибка 0.1).** Размер ответа сравнивается в символах (`< 90000`), а лимит CacheService — 100 КБ в байтах; кириллица — 2 байта на букву. Если ответ превысит лимит, `cache.put` бросит ошибку внутри `try`, и всем уйдёт «Не удалось прочитать таблицу». Сейчас данных ~11 КБ за 7 недель → к концу учебного года подойдём к границе. Исправление (шаг 2): ошибка кэша не ломает ответ; большой ответ кладётся в кэш кусками по 30 000 символов (`putAll`); ключ кэша меняется на `payload-v2`, чтобы сразу ушёл старый ответ с именами.
- **Имя последнего правившего видно в редакторе** (`admin.js`, строка статуса пары) — убирается в шаге 2.
- **Проверки редактора зависят от сегодняшней даты:** редактор открывает неделю по настоящим часам, а сценарии рассчитаны на 2–7.11. С пятницы 6.11, 12:00 они начнут падать — и на GitHub это остановило бы выкладку. Шаг 1: `?now=` в редакторе, как уже есть на странице группы.
- `data.template.find(...)` встречается в 4 модулях (перенос, Telegram, помощники, редактор) — заменяется поиском пары по версии на дату (шаг 3).

## Ключевые решения 0.2 простыми словами
1. **Шаблон хранится версиями «с даты».** Новая версия — копия текущей; старые недели собираются по старой версии, поэтому прошлое не меняется. Действующую версию не правим — делаем новую «с завтра».
2. **Пары сохраняют свои номера (`id`) при копировании** — ДЗ и замены остаются привязанными к ним.
3. **До сохранения видно последствия** — какие ДЗ, замены и переносы задеты; ничего не удаляется молча.
4. **Импорт ищет пару по дню и времени**, расписание из сообщения не меняет, всё спорное — в отдельный список.
5. **Имена активистов только в таблице**; сервер вырезает их из всех ответов.
6. **Перед каждой выкладкой — браузерные проверки на GitHub**; для этого добавляется одна зависимость для разработки — Playwright.

Термины: **devDependency** — пакет, нужный только разработчику для проверок, в сайт не попадает. **package-lock.json** — файл с точными версиями пакетов, чтобы на GitHub ставилось ровно то же. **OG-теги** (Open Graph) — строки в коде страницы, из которых мессенджеры собирают превью ссылки. **Миграция** — однократное преобразование данных под новую структуру.
